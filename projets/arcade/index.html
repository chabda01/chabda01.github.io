Arcade

Une borne d'arcade dont le programme principal ne sait ni dessiner ni jouer. Il charge à chaud une bibliothèque d'affichage et une bibliothèque de jeu, et les fait parler à travers une interface commune. On peut donc changer d'affichage en pleine partie sans rien perdre.

Projet de groupe, à trois, écrit en C++. Ma part : les jeux Snake et Nibbler (avec ses 32 niveaux) et la bibliothèque d'affichage ncurses. Mes coéquipiers ont écrit le cœur, les affichages SDL2 et SFML, Minesweeper et Breakout. Cette page en est une version web : les mêmes règles et la même interface, que j'ai réécrites en JavaScript pour qu'elles tournent dans votre navigateur.

$ ./arcade ./lib/arcade_ncurses.so Prêt

Le programme s'est terminé (code 0).

Cliquez sur l'écran pour jouer au clavier, ou utilisez les boutons. Maj + Tab rend le clavier à la page.

        L'interface IDisplay (copiée du projet)

class IDisplay {
public:
    virtual ~IDisplay() = default;

    virtual void init() = 0;
    virtual void close() = 0;

    virtual void clear() = 0;
    virtual void render() = 0;

    virtual void drawCell(int x, int y, const Cell &cell) = 0;
    virtual void drawText(int x, int y, const std::string &text,
                          Color fg = Color::WHITE) = 0;

    virtual Key getInput() = 0;

    virtual int getWidth() const = 0;
    virtual int getHeight() const = 0;

    virtual void showGameIntro(const std::string &name) { (void)name; }
    virtual char getChar() { return 0; }
};

struct Cell { char symbol; Color fg; Color bg; };

extern "C" arcade::IDisplay *createDisplay();
extern "C" void destroyDisplay(arcade::IDisplay *display);

      

      

        L'interface IGame (copiée du projet)

class IGame {
public:
    virtual ~IGame() = default;

    virtual void init(int width, int height) = 0;
    virtual void close() = 0;

    virtual void update(float deltaTime) = 0;
    virtual void handleInput(Key key) = 0;

    virtual void render(IDisplay &display) = 0;

    virtual bool isOver() const = 0;
    virtual int getScore() const = 0;
    virtual std::string getName() const = 0;
};

extern "C" arcade::IGame *createGame();
extern "C" void destroyGame(arcade::IGame *game);

      

    

  






  

    
Comment tester

    
    
      
  1. Cliquez sur l'écran, puis appuyez sur Entrée. Le clic passe l'accueil de ncurses, Entrée lance Snake depuis le menu. Le serpent se dirige avec les flèches, Espace l'accélère.
    2. 
      
  2. En pleine partie, appuyez sur Tab. L'affichage passe de ncurses à SDL2, puis à SFML. Le serpent, la pomme et le score ne bougent pas : à droite, « Jeu chargé » garde la même instance, seul l'affichage est déchargé et rechargé.
    3. 
      
  3. Changez de jeu avec F2 puis R. F2 choisit le jeu suivant, R le charge. Le journal montre le dlclose de l'ancien jeu et le dlopen du nouveau.
    4. 
      
  4. Essayez les quatre jeux. Nibbler : face à un carrefour, vous avez 3 secondes pour choisir. Minesweeper : Espace révèle, Entrée pose un drapeau. Breakout : Espace lance la balle, une flèche lance la raquette, une autre touche l'arrête.
    5. 
      
  5. Perdez, puis regardez le menu. Le score part dans scores.txt et le meilleur de chaque jeu s'affiche. N dans le menu permet de saisir votre nom avant de jouer.
    6. 
    

  

  

    
Comment ça marche

    
Le cœur ne connaît que deux interfaces : IDisplay pour dessiner et lire le clavier, IGame pour les règles. Au démarrage, il ouvre chaque fichier .so du dossier ./lib et regarde s'il contient createDisplay ou createGame. C'est ainsi qu'il trie les affichages et les jeux, sans liste écrite en dur.

    
    
À chaque image, le cœur lit une touche (getInput), la donne au jeu (handleInput), fait avancer le temps (update), puis demande au jeu de se dessiner (render). Le jeu n'envoie que des cases : un caractère, une couleur de texte, une couleur de fond. Chaque affichage en fait ce qu'il veut : ncurses écrit le caractère, SFML dessine un rond avec des yeux pour la tête du serpent.

    
Comme tout l'état de la partie est dans l'objet du jeu, changer d'affichage revient à fermer une bibliothèque et à en ouvrir une autre. Le jeu ne s'en rend pas compte.

Ce qui change par rapport au vrai programme

    
    
      
  • Les .so, dlopen et les adresses sont simulés : ici, une « bibliothèque » est un objet JavaScript. L'ordre des appels est celui du cœur d'origine.
    • 
      
  • J'ai comparé les quatre jeux aux vrais, compilés à part : sur 160 parties rejouées avec le même hasard, les appels d'affichage sont identiques un à un.
    • 
      
  • Dans le dépôt, ncurses ne traduit pas la barre d'espace. Je l'ai ajoutée ici pour que tous les jeux soient jouables dans les trois affichages.
    • 
      
  • L'introduction de ncurses dure 7,5 secondes dans le vrai programme. Ici elle est raccourcie et ne passe qu'une fois, sauf si vous cochez la case.
    • 
      
  • Pas de son. Les polices sont celles de la page. scores.txt est gardé dans votre navigateur, au même format.
    • 
      
  • Les boutons à l'écran et le champ de saisie du nom sont ajoutés pour le tactile.
    • 
    

  






  
À quoi ça sert en entreprise

  

    
Changer de fournisseur sans tout réécrire
Un logiciel qui parle à son moyen de paiement, sa base ou son imprimante à travers une interface peut en changer sans toucher au métier. C'est le même principe que nos trois affichages.

    
Ajouter des modules sans arrêter le service
Charger et décharger du code pendant que le programme tourne, c'est la base des systèmes à greffons : un outil interne reçoit une nouvelle fonction sans être redéployé en entier.

    
Travailler à plusieurs équipes
Une interface décidée ensemble permet à deux équipes d'avancer chacune de son côté et de brancher leurs parties à la fin. Nous l'avons vécu avec l'autre groupe.
