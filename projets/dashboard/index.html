Dashboard

Un tableau de bord que l'on héberge soi-même. Chacun compose sa page avec des widgets : météo, GitHub, Hacker News, taux de change, flux RSS, Gmail. Chaque widget se rafraîchit à son propre rythme.

Projet de 3e année, fait à deux. Ma part est le frontend, écrit en TypeScript avec Next.js, React et Tailwind. Le backend (API, base de données, connexion aux services) est le travail de mon binôme : il n'est pas branché ici. Cette page est une version web autonome de mon frontend, réécrite en JavaScript sans bibliothèque. Les widgets y lisent des données d'exemple fictives.

Comment tester

  1. Regardez une carte se rafraîchir. Chaque carte a son compte à rebours, en bas à droite. À zéro, une ligne GET /dashboard/widgets/…/data arrive dans le journal et l'heure « Actualisé à » change.
  2. Ajoutez un widget. Cliquez sur « + Ajouter un widget », choisissez « Température d'une ville », écrivez Lyon et mettez 10 secondes. La carte arrive en fin de tableau.
  3. Trompez-vous exprès. Tapez Lyon69 : les chiffres sont refusés pendant la frappe. Ajoutez un taux de change vers XOF : le serveur répond 422 et la carte liste les devises disponibles, avec un bouton pour corriger.
  4. Déplacez une carte. Glissez-la sur une autre : elles échangent leur place. Au doigt, gardez l'appui un court instant avant de glisser. Au clavier : Tab, Espace, les flèches, puis Espace.
  5. Ouvrez le menu « ••• ». Agrandir, Reconfigurer (pour changer la ville ou le rythme), Supprimer. Rechargez la page : votre tableau est toujours là. « Tout réinitialiser » remet l'exemple de départ.

Pour finir, cliquez sur « Panne météo ». Au prochain rafraîchissement, les cartes météo gardent leurs dernières données et affichent une alerte rouge.

Comment ça marche

Le frontend ne connaît aucun widget à l'avance. Au chargement, il lit GET /about.json : la liste des services, des widgets et de leurs paramètres. Il construit le formulaire à partir de cette liste. J'y ajoute seulement les libellés en français et les valeurs par défaut.

Chaque carte donne son rythme à un Timer central. Quand le Timer sonne, la carte relit ses données. Si la lecture échoue, la carte garde ses dernières données et affiche l'erreur à côté.

Le déplacement est un échange : la carte lâchée prend la place de celle qu'elle recouvre, les autres ne bougent pas. Le frontend envoie ensuite deux PATCH, l'un après l'autre, pour enregistrer les deux nouvelles positions.

Nos choix techniques

Pour chaque couche du frontend, nous avons essayé trois outils avec un petit prototype avant de choisir : Next.js, Vite + React ou SvelteKit ; Tailwind, CSS Modules ou styled-components ; dnd-kit, react-beautiful-dnd ou le glisser-déposer natif du navigateur. Le glisser-déposer natif ne marche pas sur un écran tactile, et react-beautiful-dnd n'est plus maintenu. Nous avons donc pris dnd-kit.

Ce qui est repris de mon code

  • Les 11 widgets des 6 services, avec leurs paramètres, leurs libellés, leurs valeurs par défaut et leurs bornes.
  • Les règles de saisie du formulaire et le rythme entre 10 secondes et 24 heures.
  • Le Timer central, l'affichage de chaque widget, le menu, le plein écran.
  • L'échange de cartes, à la souris (après 4 px), au doigt (après 200 ms d'appui) et au clavier ; la touche Retour arrière supprime la carte qui a le focus.

Ce qui est simulé

  • Le backend. Le faux serveur garde les mêmes routes, les mêmes contrôles, les mêmes codes d'erreur et la même règle de cache que le vrai. Dans le vrai projet, c'est le Timer du serveur qui remplit le cache ; ici, il se remplit au moment de la lecture.
  • Les données. La météo, les dépôts « atelier-nord », les titres, les mails et les taux sont inventés. Ils bougent plus vite que dans la réalité pour que l'on voie les rafraîchissements.
  • La sauvegarde. Dans le vrai projet, le tableau est gardé en base de données, par utilisateur. Ici, il est gardé dans votre navigateur.

Ce que j'ai ajouté pour cette page

  • Le compte à rebours et la petite barre sous chaque carte, le journal des appels, les compteurs.
  • Les tableaux d'exemple, les valeurs proposées sous les champs, le bouton « Panne météo ».

Ne sont pas montrés ici : la création de compte, la connexion, le lien avec un compte GitHub ou Google, la page Services, le panneau d'administration, le thème clair du tableau et la position sur l'horloge.

À quoi ça sert en entreprise

L'écran d'une équipe produit

Les derniers commits, les tickets ouverts, les mails et la météo du bureau sur un seul écran. Au point du matin, tout le monde regarde la même chose.

La veille sans dix onglets

Un flux RSS par concurrent ou par sujet, une recherche par mot-clé sur Hacker News. On voit ce qui est nouveau d'un coup d'œil.

Des chiffres externes à portée de main

Un service achats ou export suit ses taux de change avec leur historique. Chaque widget a son rythme, ce qui évite d'interroger trop souvent les services payants.
