Raytracer

Un moteur qui calcule une image 3D à partir d'un simple fichier texte. Pour chaque pixel, il lance un rayon dans la scène et calcule la couleur de ce qu'il touche : formes, lumières et ombres.

Le projet d'origine est écrit en C++. Cette page en est une version web : j'ai réécrit les mêmes calculs en JavaScript, avec le même format de fichier, pour qu'ils tournent dans votre navigateur.

Prêt

Glissez sur l'image pour faire tourner la caméra autour de la scène. Le fichier à côté se met à jour.

Aide-mémoire du format
cameraresolution, position, rotation (x : haut-bas, y : gauche-droite, en degrés), fieldOfView. L'axe Z pointe vers le haut.
spheresx, y, z, r (rayon), color
planesaxis ("X", "Y" ou "Z"), position, color ; damier : checker, checkerScale, checkerColor
cylinderscenter, axis, radius, color (cylindre infini)
cylindreslimitescomme cylinders, plus height
conesapex (pointe), axis, angle, color
coneslimitescomme cones, plus height
conesfantomescomme cones, avec les deux nappes
trianglesv0, v1, v2, color
lightsambient (0 à 1), directional (x, y, z : direction), point (x, y, z : position) ; color en option

Les couleurs vont de 0 à 255. L'angle d'un cône est lu en radians, comme dans le projet d'origine (la valeur va directement dans une tangente).

Comment tester

  1. Choisissez une scène. Cliquez sur « Cône fantôme » ou « Packshot produit ». L'image apparaît d'abord en gros carrés, puis elle s'affine.
  2. Changez une valeur. Dans le fichier, modifiez la couleur d'une sphère (r, g, b de 0 à 255) ou son rayon, puis cliquez sur « Rendre ».
  3. Déplacez une lumière. Dans le bloc lights, changez x, y ou z. Les ombres bougent avec elle.
  4. Tournez autour. Glissez sur l'image. La caméra tourne autour de la scène, et sa position se réécrit dans le fichier.
  5. Cassez le fichier. Supprimez une accolade ou un champ. La page vous dit quelle ligne pose problème, et garde la dernière image.

Comment ça marche

Un écran, c'est une grille de pixels. Pour chacun, le programme se pose une question : « qu'est-ce que la caméra voit dans cette direction ? »

  1. Lire le fichier. Il décrit la caméra, les formes et les lumières.
  2. Lancer un rayon par pixel. Le rayon part de la caméra et traverse le pixel.
  3. Trouver ce qu'il touche. Chaque forme a sa formule : sphère, plan, cylindre, cône, triangle. On garde l'objet le plus proche. Si rien n'est touché, le pixel reste noir.
  4. Regarder vers chaque lumière. Un second rayon part du point touché. Si un objet est sur le chemin, le point est à l'ombre. Sinon, plus la surface fait face à la lumière, plus elle est claire. S'y ajoute un petit reflet brillant (modèle de Phong).
  5. Assombrir les creux. Seize rayons courts partent autour du point. Plus ils sont bloqués, plus le point est sombre. C'est ce qui marque le contact entre un objet et le sol.

Ce qui change par rapport au C++

Le projet d'origine écrit un fichier image PPM et ouvre une fenêtre. Chaque forme y est un plugin chargé au démarrage, et le fichier est lu par la bibliothèque libconfig++. Ici, j'ai écrit un petit lecteur pour ce même format.

J'ai ajouté pour le web : le calcul en arrière-plan avec affichage progressif, le choix de la largeur, la caméra à la souris, l'export PNG et un cache : une image déjà calculée est gardée dans votre navigateur et s'affiche tout de suite la fois suivante. Le code C++ contient aussi des reflets miroir et de la transparence, mais le fichier de scène ne permet pas de les régler : je ne les ai pas repris.

À quoi ça sert en entreprise

Visuels de produit

Montrer un produit sous plusieurs couleurs ou plusieurs angles sans refaire de séance photo. Ici, changer une teinte revient à changer une ligne.

Maquettes et avant-projets

Poser des volumes simples, déplacer le soleil et voir où tombent les ombres avant de lancer une étude plus lourde.

Images produites par un script

La scène est un fichier texte. Un programme peut donc l'écrire, la versionner et lancer des séries de rendus sans intervention.

Ce que ce projet montre

Du C++ orienté objet, une architecture à plugins, un format de fichier à lire proprement, et des maths appliquées qu'il faut vérifier par des tests.
